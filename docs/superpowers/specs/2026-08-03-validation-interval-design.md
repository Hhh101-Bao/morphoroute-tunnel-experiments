# MMDetection 验证间隔修正设计

## 目标

将正式 MMDetection 训练的 D2 验证与检查点间隔从每 1000 次优化器更新调整为每 5000 次优化器更新，减少验证开销，同时保留已经完成的训练进度。

## 范围

- 所有通过统一 MMDetection 配置生成器运行的 Mask R-CNN、Mask2Former 和 MorphoRoute 实验使用同一规则。
- 新增可冻结参数 `validation_update_interval`，正式配置默认为 5000。
- `max_updates < 100` 的冒烟测试默认每次优化器更新验证，避免短测试没有验证结果。
- 验证间隔按优化器更新定义；写入 MMEngine 时乘以梯度累积次数。例如累积 8 时，5000 次优化器更新对应 40000 个微迭代。
- 检查点保存间隔与验证间隔保持一致，确保每个候选检查点都有对应 D2 指标。

## 不改变的内容

- 不修改 640 输入尺寸、有效 batch=8、AMP、AdamW、学习率、调度器或损失函数。
- 不删除或改写现有 `outputs`、日志、最近完整检查点和最佳检查点。
- 不改变 D1/D2/D3/D4 的数据职责。

## 恢复策略

当前进程仍持有旧配置，源代码修改不会在进程内自动生效。应在最近一次验证结束后中断，再用原 EXP-04 命令恢复。运行器从 `last_checkpoint` 读取最近完整检查点；本设计核验时该检查点为 `iter_16000.pth`。新配置下一次验证发生在 40000 微迭代，已经写入检查点的区间不重新训练。

## 验证

- 回归测试验证 50000 更新、累积 8 时 `val_interval` 和检查点 `interval` 均为 40000。
- 回归测试验证显式覆盖参数能够生效。
- 回归测试验证短冒烟任务仍产生验证。
- 运行相关测试文件和配置空运行，不启动长时间训练。
